# PC 项目与 MainApi Dashboard 功能说明书

## 1. 文档目的

本文用于说明 `pc` 项目与 `MainApi` 中 `Dashboard` 后台的主要功能、典型操作流程、数据同步关系以及当前版本的重要行为规则，方便日常使用、培训交接、排查问题和后续维护。

适用范围：

- PC 订单录入与识别客户端
- MainApi Dashboard 后台管理页面
- 商品编码、周期设置、价格规则、业务群、订单管理、机器码管理相关流程

---

## 2. 系统组成

系统分为两个主要部分：

### 2.1 PC 客户端

PC 客户端负责一线订单处理，核心职责包括：

- 登录主服务
- 粘贴或录入订单原文
- 解析订单文本
- 按周期 / 型号 / 度数匹配商品编码
- 人工审核待确认项
- 上传订单到服务器
- 查看历史记录与执行取消订单

### 2.2 MainApi Dashboard 后台

Dashboard 负责管理服务器侧的基础数据和上传结果，核心职责包括：

- 维护用户账号
- 维护业务群与余额
- 查看和管理已上传订单
- 维护商品编码目录
- 维护周期设置与周期对照
- 维护价格规则
- 维护机器码白名单

---

## 3. 角色与入口

### 3.1 PC 客户端入口

主程序：`pc/bin/Debug/net6.0-windows/SmartOrder.exe`

PC 登录成功后进入主界面，默认按以下顺序处理当前批次：

1. 解析
2. 审核
3. 上传

### 3.2 Dashboard 入口

后台页面目录：`MainApi/Dasbord`

常用页面包括：

- `login.html`：后台登录
- `index.html`：用户管理
- `business.html`：业务群管理
- `orders.html`：订单管理
- `product-catalog.html`：商品编码管理
- `settings.html`：周期设置
- `price-rules.html`：价格规则管理
- `machine-codes.html`：机器码管理

### 3.3 角色权限

当前后台主要有两类角色：

- `manager`：管理员
- `user`：普通后台使用者/客服

权限特点：

- 管理员可进入全部后台页面
- 普通用户可进入业务群、订单、价格、商品编码、周期设置
- 机器码管理和用户管理仅管理员可用

## 4. PC 客户端功能说明

## 4.1 登录窗口

登录窗口用于连接 MainApi 并校验当前设备与账号。

主要行为：

- 输入主服务账号和密码
- 登录前会读取本机机器码
- 先校验机器码，再校验账号密码
- 登录成功后才保存账号密码
- 如果账号被清空且登录未成功，下次不会继续回填旧账号密码

当前机器码相关规则：

- 若机器码未注册，会提示“请联系管理员注册本设备”
- 同时自动尝试打开 `MachineCodeTool.exe`
- 该工具当前要求放在主程序 `debug` 根目录

适用场景：

- 新电脑首次部署
- 机器码未录入后台
- 设备更换后重新授权

## 4.2 主界面标签页

主界面当前主要包含以下标签页：

- `录入工作台`
- `处理信息`
- `设置中心`
- `训练语义`
- `历史记录`

其中核心工作区域是 `录入工作台` 和 `设置中心`。

## 4.3 录入工作台

录入工作台用于订单文本处理，是日常使用频率最高的功能区。

主要按钮：

- `解析文本`
- `清空文本源`
- `查询文本源`
- `上一个`
- `下一个`
- `校验当前订单`
- `跳过当前订单`
- `上传当前订单`
- `批量上传待审订单`

主要功能：

- 输入或粘贴原始订单文本
- 自动解析订单号、收货人、电话、地址、备注、商品项
- 将商品项拆分为可识别的订单明细
- 对当前订单逐条审核后上传

## 4.4 解析文本前的服务器同步机制

当前版本中，用户每次点击“解析文本”前，客户端会先执行一次轻量同步检查。

同步逻辑如下：

1. 拉取服务器最新周期设置
2. 获取服务器商品编码最后更新时间
3. 将服务器更新时间与本地商品编码 JSON 文件时间戳比较
4. 如果服务器较新，则弹出“同步服务器商品编码中，请稍候…”提示窗
5. 回拉最新商品编码与缺货状态
6. 同步完成后关闭提示窗，再继续解析订单

这样做的目的：

- 不做全量常驻同步
- 不做服务器推送
- 尽量减少网络开销
- 保证解析前尽量拿到最新周期设置和商品编码目录

当前特点：

- 周期设置：解析前会同步
- 商品编码：只有服务器比本地新时才回拉
- 缺货状态：跟随商品编码同步一起更新

## 4.5 商品识别逻辑

PC 端识别商品时，核心仍然围绕三要素：

- 周期
- 型号
- 度数

主要规则：

- 型号加度数必须匹配
- 如果描述中已明确写出周期，则优先按明确周期匹配
- 只有商品项本身没有明确周期时，才允许继承订单级周期
- 商品项三要素已完整时，不应被整单默认周期错误覆盖
- 找不到完全符合的编码时，应按未匹配或待确认处理，不应强行落到其他度数或其他周期

当前还加入了固定规则兜底，用于提升周期识别稳定性，例如：

- `日抛2片装` 与 `日抛2片`
- `两片` 与 `2片`
- 带不带 `装`
- 中文数字片数与阿拉伯数字片数

若目录标准周期只有 `日抛2片`，而原文只写 `日抛`，系统会按固定规则兜底归一到 `日抛2片`。

## 4.6 商品编码人工确认窗口

当商品无法直接完全命中时，可打开商品编码选择窗口人工确认。

窗口作用：

- 查看候选商品编码
- 人工选择正确编码
- 处理周期相近、型号相近但度数不同的情况
- 处理目录里存在多个近似候选的情况

当前版本的候选优先规则：

- 如果当前商品项已经识别出周期，则候选默认优先同周期项
- 候选排序优先 `WearMatched` 的结果
- 避免“半年抛”压过“日抛2片”这类错误默认项

## 4.7 缺货状态处理

商品编码支持后台配置缺货。

客户端行为分两种：

### 4.7.1 自动匹配到缺货商品

- 系统会标识该商品缺货
- 若尚未人工确认，仍属于待处理状态

### 4.7.2 人工确认后的缺货商品

当前逻辑已调整为：

- 人工确认缺货商品后，不再保持“待确认”
- 状态应视为“完全匹配 + 缺货”
- 保留缺货的视觉提示
- 背景仍按缺货样式显示，便于审核人员识别

这意味着：

- 缺货本身的业务逻辑不变
- 但只要人工已确认正确编码，就不该再因为“待确认”阻止后续操作

## 4.8 上传前校验与阻止上传规则

当前上传前会进行订单校验，若存在问题会阻止上传，并把问题项列出来。

当前阻止上传的主要情况：

1. 订单整体校验不通过
2. 存在未匹配商品
3. 存在待确认商品

说明：

- “未匹配商品”会直接列出对应商品项
- “待确认商品”会列出对应商品项
- 当前代码里“仅因缺货直接阻止上传”的文案已被注释，不单独按缺货生成一条阻止原因
- 但如果缺货商品没有完成人工确认，通常仍会因为“待确认”而被拦下

适合理解为：

- 缺货不是单独的文案阻断项
- 未确认才是实际阻断项

## 4.9 设置中心

设置中心用于维护本地工作所需的识别与映射数据。

当前包含以下子页签：

- `周期列表`
- `周期对照表`
- `商品编码列表`
- `编码对照表`
- `账号 ERP 映射`
- `接口配置`

常用按钮：

- `保存设置`
- `导入设置`
- `导出设置`
- `新增当前行`
- `删除当前行`
- `查询订单记录`
- `查询商品编码`

各模块说明：

### 周期列表

维护标准周期值，供识别归一使用。

### 周期对照表

维护别名与标准周期的映射，例如把不同写法统一到同一标准周期。

### 商品编码列表

维护本地商品目录，是解析识别的重要基础数据。

### 编码对照表

用于处理特殊文本与商品编码之间的映射关系。

### 账号 ERP 映射

维护上传账号与 ERP 账号等业务字段的对应关系。

### 接口配置

维护 MainApi 地址、登录账号、机器码等连接参数。

## 4.10 历史记录

历史记录页主要用于追踪已处理订单和取消订单。

支持功能：

- 按订单号查询
- 按收件人查询
- 按时间范围筛选
- 重置筛选
- 查看原始文本
- 查看订单快照
- 查看接口返回结果
- 执行取消订单

当前历史数据特点：

- 本地有审计记录
- 历史页会尝试与服务器记录同步
- 若服务器同步失败，会先显示本地数据，不影响查看

## 4.11 训练语义

当前界面中保留了训练语义区域，主要用于：

- 带入当前文本
- 生成当前解析结果
- 保存训练样本
- 应用到语义

该区域当前默认隐藏或低频使用，主要面向调试、训练与语义优化场景。

## 5. MainApi Dashboard 功能说明

## 5.1 后台登录

登录页用于后台身份验证。

当前行为：

- 使用后台账号密码登录
- 登录成功后根据角色跳转默认页面
- `manager` 默认进入用户管理
- `user` 默认进入业务群管理

## 5.2 用户管理

页面：`index.html`

主要功能：

- 查询账号
- 新增账号
- 编辑账号
- 删除账号

维护字段：

- 登录账号
- 登录密码
- ERP ID
- 角色

适用场景：

- 新增客服账号
- 修改后台登录密码
- 调整 ERP 对应关系
- 调整权限角色

## 5.3 业务群管理

页面：`business.html`

主要功能：

- 查看业务群列表
- 新增业务群
- 修改业务群余额
- 删除业务群
- 进入该业务群的订单管理页

业务群卡片上通常展示：

- 业务群名称
- 当前余额
- 订单数

适用场景：

- 业务群开户
- 日常余额维护
- 按群查看订单

## 5.4 订单管理

页面：`orders.html`

主要功能：

- 查看某个业务群下的订单
- 按日期范围筛选
- 重置筛选
- 导出订单
- 编辑订单金额和快递单号
- 删除订单
- 查看完整商品详情

当前界面会区分一些特殊价格情况：

- 价格多付
- 清仓
- 订单已取消

### 订单商品详情弹窗

商品详情弹窗当前可展示：

- 商品名称
- 商品编码
- 数量
- 当次识别到的价格标签
- 当次识别到的单副价格

说明：

- 只有当时计算价格时确实识别到了价格，才显示价格信息
- 如果当时没有识别到价格，则不显示价格字段

这部分的意义是：

- 后台查看订单时能知道当次到底按什么价格规则算的
- 便于人工复核金额来源

## 5.5 商品编码管理

页面：`product-catalog.html`

这是 Dashboard 中最关键的基础数据维护页面之一。

主要功能：

- 下载模板
- 覆盖导入
- 增量导入
- 缺货导入
- 到货导入
- 新增商品编码
- 导出目录
- 按条件检索
- 按分组维护周期与价格周期
- 按明细维护商品编码、条码、缺货状态

筛选条件包括：

- 综合搜索
- 周期
- 价格周期
- 型号
- 度数

页面结构特点：

- 左侧或主体区域按 `周期 + 型号` 分组展示
- 右侧展示该组下的度数明细

明细维护字段常见包括：

- 度数
- 商品编码
- 条码
- 价格周期
- 是否缺货

### 商品编码导入模式说明

当前支持至少以下导入模式：

- 覆盖导入
- 增量导入
- 缺货导入
- 到货导入

建议理解如下：

- 覆盖导入：以导入文件为准整体覆盖对应内容
- 增量导入：新增或更新已有条目，不必整体重建
- 缺货导入：批量把对应商品标记为缺货
- 到货导入：批量把对应商品恢复为有货

### 缺货维护

可直接在商品编码明细行上执行：

- 标记缺货
- 取消缺货

这部分数据会影响 PC 端的商品识别与审核展示，并在客户端下次解析前同步时被拉取。

### 价格周期

当前商品编码中除了识别周期，还支持维护价格周期。

用途：

- 避免价格规则缺失时无法正确匹配
- 为价格计算提供单独的周期维度

## 5.6 周期设置

页面：`settings.html`

主要功能：

- 维护标准周期列表
- 维护周期对照表
- 保存周期设置

周期设置的作用范围很大，会影响：

- 商品编码导入
- 周期识别
- 商品匹配
- PC 登录后同步
- PC 解析前同步

建议使用方式：

- 周期列表中保存标准周期名称
- 周期对照表中保存常见别名、口语写法、简写写法

例如：

- `日抛两片`
- `日抛2片`
- `日抛2片装`

可统一归一到一个标准周期。

## 5.7 价格规则管理

页面：`price-rules.html`

主要功能：

- 下载模板
- 导入价格规则
- 新增价格规则
- 编辑价格规则
- 删除价格规则
- 搜索和排序价格规则

当前价格规则分三类：

1. `base`：单副价
2. `bulk`：多付活动
3. `clearance`：清仓规则

规则大意如下：

### 单副价

- 按价格周期统一生效
- 不再区分型号

### 多付活动

- 用于整包数量触发的活动价

### 清仓规则

- 可按指定型号集合和数量生效

页面中常见字段：

- 规则类型
- 价格周期
- 型号集合
- 整包数量
- 价格

适用场景：

- 维护常规单副单价
- 维护多付优惠
- 维护清仓组合价格

## 5.8 机器码管理

页面：`machine-codes.html`

主要功能：

- 查询机器码
- 新增机器码
- 编辑机器码描述
- 删除机器码

维护字段：

- 机器码
- 描述
- 创建时间

用途：

- 控制哪些电脑允许登录 PC 客户端
- 防止未授权设备接入业务系统

建议做法：

- 新电脑部署前先在后台录入机器码
- 机器码描述尽量写清使用人或设备信息

## 6. PC 与 Dashboard 的数据关系

## 6.1 周期设置

维护入口：

- Dashboard `周期设置`
- PC `设置中心`

当前运行策略：

- 服务器作为最新周期设置来源
- PC 在解析前主动同步服务器周期设置

## 6.2 商品编码

维护入口：

- Dashboard `商品编码管理`
- PC 本地也保存商品编码 JSON

当前运行策略：

- PC 不做每次全量拉取
- 先比较服务器 `last-updated` 与本地 JSON 时间戳
- 仅服务器较新时回拉目录

这样可以兼顾：

- 使用体验
- 同步及时性
- 网络压力

## 6.3 缺货状态

维护入口：

- Dashboard 商品编码页

同步方式：

- 随商品编码目录同步一起进入 PC

影响范围：

- PC 商品识别结果
- 审核状态
- 上传前阻断判断

## 6.4 价格规则

维护入口：

- Dashboard `价格规则管理`

作用：

- 订单上传后后台展示金额来源
- 订单明细页可查看识别到的价格标签与单价

## 7. 典型操作流程

## 7.1 新电脑首次上线

1. 在 Dashboard 新增机器码
2. 将 PC 主程序与 `MachineCodeTool.exe` 部署到目标电脑
3. 打开 PC 客户端
4. 输入主服务账号密码登录
5. 若未注册机器码，联系管理员在后台补录
6. 登录成功后进入主界面

## 7.2 日常解析订单

1. 打开 PC 客户端并登录
2. 粘贴订单原文
3. 点击“解析文本”
4. 等待周期设置和商品编码同步检查完成
5. 查看自动识别结果
6. 处理未匹配、待确认或缺货项
7. 点击“校验当前订单”
8. 无阻断项后上传

## 7.3 更新商品编码后立即生效

1. 在 Dashboard 商品编码页修改商品编码或缺货状态
2. 保存后无需服务器推送
3. 回到 PC，下一次点击“解析文本”时会：
4. 先拉周期设置
5. 再检查商品编码更新时间
6. 若服务器版本较新，则自动同步最新目录
7. 同步提示窗关闭后继续解析

## 7.4 处理缺货商品

1. 在 Dashboard 标记某个商品编码为缺货
2. PC 下次解析前同步到最新目录
3. 订单识别时看到缺货标识
4. 人工确认编码后，状态应视为完全匹配但保留缺货显示
5. 再根据业务决定是否允许继续处理

## 7.5 后台复核订单价格

1. 进入业务群
2. 打开订单管理页
3. 查看订单商品详情弹窗
4. 检查商品详情中的价格标签与识别单价
5. 若未显示价格，说明当次未识别到对应价格信息

## 8. 常见问题说明

## 8.1 为什么后台改了缺货，客户端没有立刻生效？

原因通常不是后台没改成功，而是客户端还没重新获取最新目录。

当前机制不是服务器主动推送，而是：

- 在 PC 点击“解析文本”前做同步检查
- 服务器商品编码比本地新时才回拉

因此：

- 只改后台但客户端不重新解析，不会立刻刷新

## 8.2 为什么有些商品明明存在，但匹配成了别的周期？

常见原因：

- 商品项本身没有稳定识别到周期
- 候选之间只剩型号和度数接近
- 周期别名没有在周期对照表里维护完整

当前版本已经增加：

- 同周期候选优先
- 周期固定规则归一
- 订单解析前同步服务器周期设置

## 8.3 为什么上传被阻止？

当前常见原因：

- 订单整体校验不通过
- 存在未匹配商品
- 存在待确认商品

系统会把具体阻断项列出来，便于逐条处理。

## 8.4 为什么后台订单详情里有的商品显示价格，有的不显示？

因为当前逻辑是：

- 当次计算价格时识别到了价格，才展示
- 没识别到则不显示

所以不显示不代表程序异常，只代表该商品当时没有形成可用价格识别结果。

## 9. 使用建议

1. 周期别名尽量在 Dashboard 周期对照表里维护完整，不要只靠本地经验处理。
2. 商品编码修改后，用一次“解析文本”触发客户端同步，不要直接沿用旧识别结果。
3. 对缺货商品，人工确认后再决定是否上传，不要把“缺货”和“未确认”混为一类。
4. 价格规则、商品编码、周期设置三者最好同步维护，避免识别正确但价格缺失。
5. 若发现识别率突然下降，优先检查商品编码目录、周期设置、周期对照和缺货导入是否刚发生变化。
